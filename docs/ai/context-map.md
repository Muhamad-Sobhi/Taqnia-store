Planned quote-entry placements are the header, secondary hero action, “Catalog coming soon” block, empty search/category results, no-price product cards, product detail page (prefill only with non-personal `sku`), and footer; none are currently present. The implemented `/en/quote` and `/ar/quote` pages show a localized unavailable state only. Bare `/quote` redirects to `/en/quote`, preserving only a valid 1–120-character SKU (`[A-Za-z0-9._-]`) and a known category slug. The future language-neutral endpoint is `POST /api/quote` with a validated locale body field. The approved quote-management workflow supports multiple products and quantities, displayed-price snapshots, per-product confirmed prices, phone/WhatsApp/email communication history, and explicit quote-to-Sales-Order conversion. See the [design-system rules](../design/design-system.md), [SEO rules](../engineering/seo.md), and [ADR-0005](../decisions/ADR-0005-quote-request-delivery-persistence.md). Cart and checkout are excluded.

Before implementation, classify quote work using the revised roadmap. Safe planning may cover dashboard IA, mock prototypes, status and transition specifications, communication interfaces, proposed permissions, proposed API contracts, localization, and accessibility. Persistence, migrations, submission handlers, customer-data storage, delivery integrations, CAPTCHA, rate limiting, idempotency, final permissions, Sales Order conversion, and production activation remain blocked.
